# 主模型与能力工具

消息进入共用 `PersonaBot` 后，由主模型根据工具说明和上下文决定怎么回复、调用哪些工具。自然语言不再由绘图/语音关键词提前分流；`/image`、`/voice` 也进入同一工具流程。主模型接收实际执行结果后组织回复，不能仅凭历史故障说接口不可用。

每轮主模型请求前按系统时钟注入北京时间（`Asia/Shanghai`）、星期和今天/昨天/明天的日期，优先于角色背景及历史聊天。聊天上下文和 `recent_requests` 均带已有数据库中的记录时间；它是机器人记录消息的时间，不保证等于平台原始发送时间。历史里的相对日期按对应记录或来源日期理解，不能把昨晚的情境当作现在。没有时间来源的记录标为未知，不补造日期；时间提示无需在普通回复中机械复述。QQ / 微信共用此逻辑，不依赖服务器本地时区，无数据库迁移。

| 工具 | 模型提供的参数 | 执行与返回 |
|---|---|---|
| `understand_images` | `question`：需要观察什么 | 从本会话最近用户图片消息选择合法附件，调用配置的识图能力，返回观察文字；不发送图片 |
| `generate_image` | `prompt`：画面描述；`reference`：`none`、`current`、`self` 或 `current_and_self` | CCR 生成/编辑图片 → 下载验证与渠道压缩 → 发图；返回 `status: sent`、`kind: image`、工作区相对路径 |
| `send_voice` | `text`：朗读内容，长度受配置限制 | CCR 合成 → 既有语音适配器转码 → QQ SILK / 微信 WAV；返回 `status: sent`、`kind: voice` |
| `research` / `web_search` / `fetch_url` / `get_weather` | 问题、关键词、公开 URL 或地区 | 沿用现有联网服务，返回来源和证据，由主模型判断如何回答 |
| `recent_requests` | 无 | 需要延续旧任务时，返回本会话最近 100 条里当前用户的原话及北京时间的记录时间，最多 12,000 字，保留完整条目；不跨会话 |

参考图也由主模型判断：画面涉及夏莉自己时自主选择 `self`，不要求用户专门说“参考图”；结合用户图片和夏莉形象时选 `current_and_self`，普通画面选 `none`。

`sent` 表示渠道 API 成功响应，不等于用户已经在手机上看过。绘图和语音工具已完成发送，不需要模型再调用 `send_file`。失败作为工具错误交回模型，不能汇报成功。

## CCR 接口与配置归属

以绘图为例，模型调用 `generate_image({"prompt":"温暖的水彩猫咪"})`，机器人使用现有鉴权发送：

```http
POST /v1/fusion/media
Authorization: Bearer <机器人客户端凭据>
Content-Type: application/json

{"model":"Fusion/qqchatbot","operation":"draw","prompt":"温暖的水彩猫咪"}
```

CCR 返回可下载的图片地址。机器人检查 HTTPS 域名、下载大小和工作区配额，微信按渠道限制压缩后发送，再把真实结果交给主模型。`reference` 需要参考图时改用 `operation: edit`，合法图片由程序选取并编码；模型不能传任意路径、URL 或其他会话 ID。

绘图/改图 HTTP 请求允许等待 170 秒，与 CCR 的 150 秒上游窗口衔接，并覆盖共享会话默认超时；普通聊天保持 110 秒。

具体绘图、改图、语音模型及音色仍在 **CCR → Fusion → qqchatbot → 工具** 配置。识图沿用 Fusion `vision_understand`；语音沿用 `/v1/voice-speech` 适配入口，由它调用 CCR 媒体接口。不增加第二套供应商配置或调度服务。

## 执行边界

- 工具清单按渠道开关和真实身份生成，执行时再次核验；昵称和模型输出不能授予权限。
- 每条消息最多一次绘图、一次语音、两次识图、一次旧请求读取、五次联网调用；模型工具循环最多十轮。同参数媒体调用复用本轮结果，失败也不重复付费重试。
- QQ 的主模型任务使用现有有界后台队列；微信使用自身持久收件队列。选中耗时媒体工具后才发对应进度，普通聊天不承诺画图/发声。
- 图片与文件来源局限当前会话；发出的表情不自动进入用户图片上下文。记忆撤销检查覆盖工具执行与最终发送。
- 发送结果不明或登录失效时停止该条消息后续操作，不能自动重发。跨消息重试必须由新入站请求提供上下文。
- Anthropic 与 OpenAI 兼容模式均执行实际工具循环。Bilibili 保留已有专用工作流；歌曲生成、微信原生语音气泡和授权文件跨端共享未新增。
