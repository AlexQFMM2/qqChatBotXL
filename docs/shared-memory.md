# 夏莉长期记忆与常驻运维

两端复用人格、模型和文件工具，各自保留聊天库、账号与工作区。共享库只保存上线后新消息中提取的长期事实；不导入旧聊天，不共享私有文件。

## 日常使用

- `/memory list [关键词]`：查看当前会话有权访问的记录，返回 ID、版本、日期和可能冲突。
- `/memory remember 事实`：显式记住，成功写入后才确认。
- `/memory edit ID 新内容`：纠正并生成新版本。
- `/memory forget ID`：遗忘；旧摘要、待处理提取以及依赖旧记录的回复和生成文件失效。
- `/memory share ID QQ群ID`、`/memory unshare ID QQ群ID`：在本人微信授权或撤销指定群。群 ID 由可信 QQ 场景取得，昵称不能代替身份。
- `/memory status` 或 `/status`：查看就绪、积压、失败、最近整理。
- `/reset`：只清当前对话，保留长期记忆和文件。

私聊事实默认只用于本人私聊。本人在 QQ 群的明确第一人称事实可以延续到本人微信；其他群成员的事实留在来源群。跨群共享须在本人微信显式授权。自动提取只读取本次实际参与的用户文字，不把模型回复、纯表情、回执或附件猜测作为事实。

`memory-identity/identities.json` 是唯一身份配置，容器只读挂载。结构为 `{"person":"teacher","qq":{"account":"QQ应用ID","owner":"唯一QQ owner"},"wechat":{"account":"微信机器人ID","owner":"可信扫码者ID"}}`。内容不得由模型、昵称或聊天指令修改；不要提交真实配置。

## 后台与权限

每个渠道运行库有独立持久提取队列。事件去重，模型失败或预算耗尽会保留待处理项。共享预算按上海自然日计算：提取最多 100 次，压缩最多 4 次；使用 `DeepSeek/deepseek-flash` 的纯文本接口，不传工具。每次检索先过滤权限，再按中文双字关键词、人物、时间排序，最多 8 条 / 3000 字。

微信实例每天 04:00（Asia/Shanghai）整理；错过后补一次。按人物及完全相同权限分别处理原事实与依据，每批最多 50 条 / 12000 字。无变化不调用模型。发布前重核版本；失败保持原有效事实和摘要。摘要只在覆盖的来源仍有效且比原文更短时用于检索。

纠正、遗忘、撤销共享在持久撤销日志完成 fsync 后才修改事实。读、检索、工具输出和发送前均验证权限 / 版本。既有短期回复记录传播版本依赖；失效内容不再用于后续模型上下文。记忆生成的文件保留在原工作区，但失效后不能再通过工具读取或回传，应重新生成。

普通聊天清理不清除长期事实。淘汰版本保留 30 天；撤销日志保留恢复所需的最新状态及永久撤销标记，淘汰文本在 30 天后移除。独立 SQLite 备份每天一次，保留 14 天。

## 部署与隔离

`wxchat-bot` 使用 Compose `wechat` profile，与 QQ 使用同一固定版本镜像。非 root、只读根文件系统、512 MiB、单消息工人、日志轮转、自动重启，无公开端口。微信数据为 `wechat-data/`，QQ 仍为原 `data/` 和 `workspace/`；只共同挂载 `shared-memory/` 与只读身份配置。

服务器 `.release.env` 固定 `QQCHAT_IMAGE`、`QQCHAT_PERSONA` 和 `MEMORY_DIR`。`.wechat-server.env` 由现有模型设置生成，不包含 QQ 凭证；所有运行凭证、库、备份和工作区均在镜像外。运行命令以该服务器实际发布记录为准，例如：

```sh
docker compose --env-file .env --env-file .release.env --profile wechat up -d --no-deps --no-build wxchat-bot
docker compose --env-file .env --env-file .release.env up -d --no-deps --no-build qqchat-bot
```

只更新指定服务，不能执行整个项目的 `down`。QQ Webhook 方式、原库和其他辅助服务保持原配置。

微信 `/app/data/health.json` 区分存活、登录就绪、最近成功轮询、积压、发送结果不明及记忆状态。健康检查检查存活；登录失效停止轮询、保留进程等维护者重登，不反复请求。重登时先停目标微信服务，再使用同一状态目录的诊断入口登录。收到 SIGTERM 会停止接收并等待当前消息最多 180 秒；超时后持久状态按中断恢复，不自动重做未知副作用。

## 切换与回滚

先通过候选镜像测试和服务器出站检查。停本机接收、等待活动任务退出后，使用 SQLite backup / 完整文件快照迁移账号、游标、库及工作区。确认本机退出，写入 `migrated.json` 后再启服务器；本机所有持有账号锁的入口都会拒绝误启动。

回滚代码只改变目标实例镜像，**不回退共享记忆目录**。微信回本机必须先停服务器、同步最新账号 / 库 / 游标 / 工作区，然后才移除本机迁出标记。不得启动旧快照来“试一下”。

## 共享库离线恢复

先停止 QQ 和微信两个目标实例；保留当前 `revocations.jsonl`、`journal-head.json` 和目录，不从旧备份覆盖它们。通过以下入口恢复单个数据库备份：

```sh
python -m app.memory restore --directory /app/shared-memory --backup /app/shared-memory/backups/YYYY-MM-DD.db
```

容器中操作时使用当前固定镜像并挂载同一目录，不能启任何渠道入口。恢复程序取得独占运行锁，校验 SQLite、日志链及独立见证，在临时库重放全部撤销记录，通过后才替换主库。任何运行实例未停止、日志缺失 / 截断 / 不匹配均拒绝恢复；原主库另留 `before-restore.db`。禁止直接复制旧 `memory.db` 覆盖线上库，禁止把整个旧共享目录回滚。
