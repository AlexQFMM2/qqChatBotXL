## 本轮实现

- 显式关联唯一 QQ owner 与可信微信绑定者；昵称、模型和聊天内容不能更改身份。共享 SQLite WAL 事实库，两端运行库各有持久提取队列。
- 仅从启用后的新参与消息积累，不导入旧聊天。纯文本 `DeepSeek/deepseek-flash` 提取，不传工具，全局每天最多 100 次；失败和预算耗尽保留待处理项。
- SQL 先过滤权限，再按中文关键词、人物和时间检索，最多 8 条 / 3000 字。私聊默认私有；本人明确第一人称群事实可在本人微信延续，跨群须显式授权。
- `/memory list [关键词]`、`remember 事实`、`edit ID 新内容`、`forget ID`、`share ID QQ群ID`、`unshare ID QQ群ID`、`status`。共享授权在本人微信管理；`/reset` 只清当前对话。
- 撤销日志先持久化，再修改事实。来源消息、旧摘要、旧回复和生成文件依赖失效，发送前复核；旧待处理提取不能恢复已撤销事实。自动矛盾事实保留来源并标记。
- 微信唯一维护者，每天 04:00 上海时间整理，错过补一次。相同人物 / 完全相同权限分批，每批 50 条 / 12000 字，每天最多 4 次；无变化零调用，事务外生成、发布前复核。
- 每日独立备份保留 14 天，淘汰文本保留 30 天；永久保留恢复所需撤销标记。日志和见证不随旧备份回退；离线恢复必须重放，日志不完整则拒绝启用。普通聊天清理不删除活跃事实。
- 微信登录失效停轮询等重登；正常退出等待当前任务最多 180 秒；健康区分存活、登录、成功轮询、积压、未知发送和记忆状态。
