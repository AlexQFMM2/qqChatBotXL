## 已确认行为

1. 用户自然表达开局意图，主模型调用工具。服务端占用唯一名额，进入环境选择，用户明确选择后机器人提示准备、CB 生成固定六候选；玩家按顺序选三只（第一只是首发），之后 CB 再生成对手三只。
2. 单打，开局可选普通、Gen7 Mega/Z、Gen8极巨化、Gen9太晶；双方固定50级，normal / balanced 对手 AI。Gen7复用正式候选的两只Mega保底并配对应石头，其余配适配的Z纯晶；玩家自由选三只。DS只转交玩家明确动作，并以夏莉第一人称回应。
3. QQ / 微信所有会话合计一局，选环境、准备和选队也占用。绑定渠道 + 会话 + 可信用户；机器人聊天对局的限制不影响原 CB 客户端对局。
4. B 的其他消息均回复“正在和其他人进行宝可梦对战，等结束再说吧。”；不调用模型、查图鉴、媒体工具或排队。A 可以闲聊，但不会续时。
5. 从环境选项就绪开始等待5分钟；成功选择环境、选队、出招后重置。查询、无效指令和 B 消息不续时；到期自动中断、不判胜负并释放名额。取消、认输、自然结束及不可恢复故障也释放。
6. 正常结束直接在最后一步回复总结，后台超时每 5 秒检查一次并向原会话通知。通知去重，失败不占名额；结果不明不自动重发，明确拒发保留待补发摘要。
7. CB 重启使内存对局失效，说明中断；qqChat 重启可以找回仍存活的局。不通过长期记忆恢复战斗规则或数值。

## 实现边界

CB 的 `apps/api` 新增 `chatBattle.ts`（单实例协调、候选/选队、操作去重、超时和结算）及 `pokemonHttp.ts`（图鉴和对战 HTTP 包装）。`chatTeam.ts` 调用现有 Gen7 正式候选保底/道具映射及其他环境的 `generateRandomBattleTeamPreviewV4`、`createInMemoryBattleService`、合法动作工具和图鉴。原 `apps/web`、`apps/desktop`、引擎规则不修改。

qqChat 新增 `app/pokemon.py`：HTTP 客户端、可信身份绑定、消息级幂等、模型工具、事实战况和终局通知。复用现有 SQLite，新增按对局保存的 `game_battle_bindings`，不会因开新局覆盖旧总结。QQ/微信分别运行，同一 CB 服务是占用状态唯一来源。

微信仅增加本局通知入口：短期保存原绑定者回复上下文，不更改普通 transport 的 active 消息。上下文过期/终局通知后清理；不能向任意联系人发消息。QQ 使用现有群发送接口。现有消息去重、权限和发送结果不明保护继续生效。

### 接口

| 接口 | 用途 |
|---|---|
| `GET /dex/search`、`GET /dex/:category/:id` | 宝可梦/招式/特性/道具搜索与详情，学招分页 |
| `GET /chat-battles/availability` | 跨渠道全局空闲、自身对局或忙碌，不泄漏他人身份 |
| `POST /chat-battles` | 原子占位并进入规则选择 |
| `POST /chat-battles/:id/configure` | 选择环境，生成固定六候选 |
| `POST /chat-battles/:id/select` | 验证三编号，生成对手并建引擎 session |
| `GET /chat-battles/:id` | 当前玩家视图；可查询指定操作是否已处理 |
| `POST /chat-battles/:id/actions` | 只接受当前合法动作 ID，执行 p1 指令 |
| `POST /chat-battles/:id/end` | 取消或认输 |

所有新入口要求启用开关与机器人专用 token，原客户端鉴权不变。绑定身份由 qqChat 生成，模型不能指定 owner、session、任意 choice 或 p2 指令。健康接口增加契约版本和进程 epoch，保留既有字段。写请求带固定操作 ID、预期 revision/epoch；重复同参数复用结果，改参数或旧版本拒绝。首次建局有 5 分钟请求有效窗。

对手信息由 p1 player stream 投影，只返回公开出场、血量和事件；不输出 full snapshot、p2 request、隐藏配招、AI 策略。固定编号保持身份，不能用换人后变化的数组下标猜测。

### 实现复核与验收覆盖

| 路径 | 本地证据 / 结论 |
|---|---|
| 入口 → 可信身份 → 全局占用（A-02/A-04） | CB 并发请求仅一个成功；QQ/微信 scope 不同即忙碌。原有命令、媒体请求、微信不支持类型和中断恢复提示均受拦截 |

| 终局 → 原会话发送（A-06/A-07） | 前台与后台同时结束仅发送一次；主动查状态发现结束也先领取通知。发送中取消/重启保留 unknown，QQ 5xx 不按明确拒发自动重试；新局保留旧局待送摘要 |
